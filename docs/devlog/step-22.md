# Step 22 — 끝이 있는 던전

**Decision:** 던전 길이를 정하고 마지막 방을 보스방으로 만들어(22a), 보스를 잡으면
`Completed` 로 끝내고 `clear` 결과를 보낸다(22b).

**Why:** 21편까지 던전이 끝나는 길은 둘뿐이었다 — `wipe`(전멸), `abandoned`(다 나감).
**성공하는 길이 없었다.** 18편부터 결과를 로비로 보내왔는데 실패만 보고하는 서버였고,
보상을 주려면 `clear` 가 있어야 한다.

**Alternatives considered:**
- **`struct Boss` 를 따로**: 로비에는 그렇게 돼 있다(Step 8). 그런데 거기선 보스가 방에
  하나뿐이고 **움직이지 않아서** 몬스터라는 개념 자체가 없었다. 배틀 서버의 보스는 쫓아오고
  때리고 맞고 죽는다 — 몬스터가 하는 일 전부다.
- **보스방도 웨이브 + 보스**: 긴장이 오래 간다. 그런데 던전 한 판이 이미 5분이 넘고,
  보스 전에 지쳐서 들어가면 **보스가 잡몹 뒤풀이**가 된다.
- **`Cleared` 를 재사용**: 문 처리 코드를 그대로 쓸 수 있다. 그런데 마지막 방에는 **다음 방이
  없다.** "문이 열렸는데 갈 데가 없다"는 상태를 만들게 된다.

**보스를 `Monster` 로 둔 것이 이 스텝에서 제일 큰 결정이다.**

```cpp
bool is_boss = false;
float speed() const { return is_boss ? kBossSpeed : kMonsterSpeed; }
int   damage() const { return is_boss ? kBossDamage : kMonsterDamage; }
```

타입을 나눴다면 `nearest_monster` · `resolve_attacks` · `resolve_monster_attacks` ·
`collect_states` 가 전부 둘로 늘어났을 것이다. 실제로 다른 건 **수치 셋과 그림 하나**뿐이다.

16편에서 `Player` 와 `Monster` 는 나눴는데 여기서는 안 나눴다. 기준은 같다 —
**하는 일이 다르면 나누고, 수치만 다르면 안 나눈다.** 플레이어는 입력을 받고 몬스터는
추적을 한다. 보스와 몬스터는 둘 다 추적한다.

**`-1` 로 시작하는 `wave_index` 가 또 쓰였다.** 보스방 스폰을 `wave_index == 0` 한 번으로
잡는다. `next_room` 이 `-1` 로 되돌리니, 보스방에 들어와 처음 `update_phase` 가 돌 때 `++` 로
0 이 되고 그때만 스폰한다. 17a 에서 특수 케이스를 없애려고 둔 것이 **세 번째 용도**를 찾았다.

**끝난 던전은 `Failed` 와 똑같이 처리한다.** `World::update` 가 맨 앞에서 돌아선다.
실패든 성공이든 "끝났다"는 점은 같고, 결과 화면 뒤에서 몬스터가 움직이면 안 된다.
18c 에서 `Failed` 에 쓴 가드에 한 줄을 더했을 뿐이다.

**테스트가 밸런스 붕괴를 드러냈다.** 보스까지 가려면 방 0 을 클리어해야 하는데, **2인으로는
클리어가 안 됐다.**

| 플레이 | 결과 |
|---|---|
| 가만히 서 있기 | 웨이브 1(32마리)에서 전멸 |
| 좌우 왕복 | 역시 전멸 — 되돌아올 때 무리 속으로 |
| 원 궤도로 끌기 | 180초에 **0킬** |

마지막이 특히 뜻밖이었다. 속도 5 로 반지름 16 궤도를 돌면 몬스터(2.5)가 **사거리 8 에 영영
못 들어온다.** 안 맞지만 안 때린다. **교착**이다.

원인이 셋 겹쳐 있다.

- 19e 에서 마릿수에 인원수를 곱했다 — 2인이면 웨이브 1 이 32마리
- 16c 의 몬스터 뭉침이 그대로다 — 한 점에 모여 접촉 피해가 곱해진다
- 사거리 8 과 속도차가 "끌면 아무 일도 안 일어난다"를 만든다

검증은 웨이브 1개 · 방 2개로 줄여서 했고, 확인 뒤 되돌렸다. **밸런스는 화면을 보면서 만질
일이라** 클라이언트가 생긴 뒤로 미뤘다 — 숫자만 돌려봐서는 "재미있는가"를 판단할 수 없다.

**테스트 도구가 또 범인이기도 했다** (일곱 번째). 첫 시도에서 루프가 한 번도 안 돌았다.

```powershell
while ($peers[0].ents -gt 2) { ... }   # ents 초기값이 0 이라 처음부터 거짓
```

고치면서 **`RoomState` 패킷으로 단계를 직접 읽게** 바꿨다. 엔티티 수로 추측하던 것을
서버가 알려주는 값으로 바꾼 셈인데, 17d 에서 `RoomState` 를 만든 이유가 정확히 이것이었다.

**현재 한계 (의도적):**
- **클리어가 불가능하다** — 위의 밸런스 문제. 클라이언트와 함께 조정한다.
- **보스가 일반 몬스터와 같은 AI** — 최근접 추적, 접촉 공격뿐이다. 패턴이 없다.
- **던전 길이가 고정 5방** — 난이도 선택이나 무한 모드가 없다.
- **`clear` 에 보상이 없다** — 로비가 결과를 받아 로그만 찍는다.
- **방마다 체력 회복** — 길이가 정해졌으니 다시 볼 값이다. 5방 내내 회복하면 압박이 없다.

**검증:** 도커 compose + 로비 클라 2쌍 + 토큰으로 입장한 UDP 피어.
(웨이브 1개 · 방 2개로 줄인 상태)

1. 방 0 웨이브 0 격파 → `room 0 cleared`
2. 문으로 이동 → `--> room 1 (monster hp 40)`
3. `room 1 BOSS ROOM` + `BOSS spawned (hp 400)`
4. 클라 스냅샷에서 **`boss=True`** (`EntityType::Boss` 로 디코딩)
5. 보스 처치 → `BOSS DOWN - dungeon COMPLETED (kills 13)`
6. 로비에
   `[dungeon] battle=5 result=clear room=1 wave=0 kills=13 players=[ian, june]`
7. 세 결과(`wipe` / `abandoned` / `clear`)가 모두 동작
